# CMT TeamSpeak Bot

بات مدیریت رول‌های **CMT Server** و **CMT Ticket**.

بات یک **کلاینت واقعی تیم‌اسپیک** را کنترل می‌کند، پس مثل یک کاربر عادی برای **همه** دیده می‌شود —
نه به عنوان ServerQuery که فقط با تیک "Show ServerQuery Clients" دیده می‌شود.
هیچ یوزر و پسورد ServerQuery ای لازم نیست.

بدون وابستگی خارجی — فقط Node.js. نیازی به `npm install` نیست.

> **راه‌اندازی روی یک دستگاه جدید؟** [SETUP.md](SETUP.md) را ببینید — راهنمای قدم‌به‌قدم از صفر.
> این فایل مرجع قابلیت‌ها و تنظیمات است.

---

## دستورات

بدون علامت `!`. بزرگی و کوچکی حروف مهم نیست.

| دستور | کار |
|---|---|
| `cmt1` یا `cmt 1` یا `cmtserver` | رول CMT Server را به **خودتان** می‌دهد. اگر از قبل داشته باشید، **می‌گیرد**. |
| `cmt1 <نام یوزر>` | همان کار، ولی روی آن کاربر. |
| `cmt2` یا `cmt 2` یا `cmtticket` | رول CMT Ticket را به خودتان می‌دهد / می‌گیرد. |
| `cmt2 <نام یوزر>` | همان کار، ولی روی آن کاربر. |
| `cmts` یا `cmt list` | لیست همه کسانی که رول CMT Server یا CMT Ticket دارند. |
| `cmthelp` یا `cmt help` | راهنمای کوتاه دستورات. |

- `CMT1`، `cmt 1`، `Cmt1` همه یکی هستند.
- دستور باید **اول پیام** باشد؛ «فلان cmt1» چیزی را فعال نمی‌کند.
- `cmt 12` به عنوان `cmt 1` با آرگومان `2` خوانده **نمی‌شود**.
- کاربر **آفلاین** هم پیدا می‌شود (از دیتابیس سرور). `dbid:123` یا Unique ID هم قبول است.

### دستور را کجا بزنیم

| جا | کار می‌کند؟ |
|---|---|
| چت **سرور** (تب Server) | ✅ از هر کجای سرور |
| **پیام خصوصی** به بات | ✅ از هر کجای سرور |
| **Poke** کردن بات (راست‌کلیک → Poke) | ✅ از هر کجای سرور |
| چت **چنل** | ⚠️ فقط اگر بات در همان چنل باشد |

**چرا چت چنل محدود است:** در تیم‌اسپیک، پیام چت یک چنل فقط برای کسانی فرستاده می‌شود که
**داخل آن چنل ایستاده‌اند**. این قانون خود پروتکل است، نه محدودیت این بات — هیچ کلاینتی
(و هیچ ServerQuery ای) نمی‌تواند چت چنلی را که در آن نیست بشنود.

پس اگر می‌خواهید از هر چنلی دستور بزنید، از **چت سرور**، **پیام خصوصی** یا **Poke** استفاده کنید.
اگر می‌خواهید چت چنل هم کار کند، بات را با `teamspeak.defaultChannelId` در همان چنل بنشانید.

## اسم چنل‌ها

اسم دو چنل مشخص‌شده با لیست دارندگان رول به‌روز می‌شود:

```
CMT Server : Ali, Reza
CMT Ticket : Mohammad
```

بعد از هر تغییر رول خودکار آپدیت می‌شود. اگر کسی رول را نداشته باشد `channels.emptyText` (پیش‌فرض `-`) می‌نشیند.
تیم‌اسپیک اسم چنل را حداکثر **۴۰ کاراکتر** قبول می‌کند؛ اگر اسم‌ها جا نشوند بات بقیه را به شکل `+3` نشان می‌دهد.

اسم‌ها **زنده** خوانده می‌شوند: نیک‌نیم فعلی کسی که آنلاین است، نه اسمی که در دیتابیس سرور مانده.

## حذف خودکار رول موقع خروج

هر کس رول CMT داشته باشد و از سرور خارج شود، رولش خودکار گرفته می‌شود.

```jsonc
"autoRemoveOnLeave": {
  "enabled": true,
  "intervalSeconds": 60   // بررسی دوره‌ای؛ 0 = فقط لحظه خروج
}
```

دو مسیر دارد: رویداد خروج (فوری، با ۳ ثانیه تأخیر تا سرور آرام شود) و یک بررسی دوره‌ای که
پشتیبان است — رویداد خروج فقط برای چنل‌های subscribe شده می‌رسد و ری‌استارت بات هم می‌تواند
از دستش بدهد.

> **محافظ:** قبل از هر حذف، بات تعداد کاربرانی که `clientlist` می‌بیند را با تعداد واقعی
> کاربران سرور مقایسه می‌کند. اگر جور نبود، **هیچ رولی حذف نمی‌شود** و اخطار می‌دهد.
> بدون این محافظ، اگر بات کسی را نمی‌دید رولش را اشتباهاً می‌پراند.
> برای همین **Subscribe to all channels** مهم است (پایین‌تر توضیح داده شده).

## کول‌داون

هر کاربر بعد از یک دستور، چند ثانیه نمی‌تواند دستور بعدی بزند — جلوی اسپم شدن سرور را می‌گیرد.

```jsonc
"cooldown": {
  "enabled": true,
  "seconds": 5,
  "exemptCommands": ["help"],   // این دستورات کول‌داون ندارند
  "exemptGroups": [],           // این گروه‌ها (مثلاً ادمین‌ها) کول‌داون ندارند
  "warnOnce": true              // فقط یک بار «صبر کنید» بگوید، نه به ازای هر اسپم
}
```

دو نکته در طراحی:

- چک کول‌داون **قبل از هر لوکاپی** انجام می‌شود. اگر بعدش بود، اسپم‌کننده همچنان همان
  ترافیکی را به سرور می‌زد که این قابلیت برای جلوگیری از آن ساخته شده.
- با `warnOnce` فقط اولین پیامِ بلاک‌شده جواب می‌گیرد. وگرنه هر اسپم یک جواب می‌گرفت و
  خودِ جواب‌ها می‌شدند ترافیک اضافه.

کاربر با **Unique ID** شناخته می‌شود نه clid، پس با ری‌کانکت کردن کول‌داون دور زده نمی‌شود.

## انتقال خودکار به چنل AFK

هر کس **دفن** کند (اسپیکر را ببندد)، بعد از چند ثانیه به چنل AFK منتقل می‌شود و وقتی
دفن را برداشت، به **همان چنلی که بود** برمی‌گردد.

```jsonc
"afk": {
  "enabled": true,
  "channelId": 44,          // آی‌دی چنل AFK
  "delaySeconds": 5,        // چند ثانیه صبر کند
  "trigger": "deaf",        // deaf (دفن) | mute (میوت میکروفون) | both
  "returnWhenBack": true,   // برگرداندن به چنل قبلی
  "pollSeconds": 2,         // هر چند ثانیه وضعیت را چک کند
  "ignoreGroups": [],       // این گروه‌ها هیچ‌وقت منتقل نشوند (مثلاً ادمین‌ها یا بات موزیک)
  "ignoreChannels": []      // از این چنل‌ها کسی منتقل نشود
}
```

برای خاموش کردنش `enabled` را `false` کنید.

رفتارهای ریز که در نظر گرفته شده:

- اگر کسی **خودش** از چنل AFK جای دیگری برود، موقع برگشتن به زور کشیده نمی‌شود.
- کسی که از قبل داخل چنل AFK نشسته، جابه‌جا نمی‌شود.
- بات خودش را منتقل نمی‌کند.
- کسی که از سرور خارج شود از حافظه پاک می‌شود.

> این قابلیت روی **poll** کار می‌کند نه فقط رویداد: در تست دیده شد رویداد
> `notifyclientupdated` موقع *برداشتن* دفن می‌آید ولی موقع *گذاشتن* دفن لزوماً نه.
> اگر فقط به رویداد تکیه می‌کرد، آدم‌ها گیر می‌کردند.

## راه‌اندازی

### ۱. کلاینت تیم‌اسپیک

کلاینت TS3 باید روی همان ماشینِ بات نصب و **باز** باشد، و پلاگین **ClientQuery** فعال باشد
(Tools → Options → Addons → ClientQuery). پلاگین روی `127.0.0.1:25639` گوش می‌دهد و
API key اش در این فایل است:

```
%APPDATA%\TS3Client\clientquery.ini
```

بات این کلید را **خودکار** از همان‌جا می‌خواند. اگر جای دیگری است، `clientquery.apiKey` یا
`clientquery.apiKeyFile` را در `config.json` پر کنید.

> **مهم:** کلاینت یک برنامه گرافیکی است و به یک سشن دسکتاپ باز نیاز دارد.
> روی ویندوز سرور، سشن RDP را **disconnect** کنید نه **log off** — لاگ‌آف کلاینت را می‌بندد.

### ۲. کانفیگ

```jsonc
"teamspeak": {
  "host": "5.57.39.100",     // آی‌پی سرور، بدون پورت
  "serverport": 11555,       // پورت ویرچوال سرور
  "nickname": "Sun Bot",     // اسمی که همه می‌بینند
  "serverPassword": "",      // اگر سرور پسورد دارد
  "defaultChannelId": 0,     // بات در این چنل بنشیند
  "autoConnect": true        // اگر کلاینت وصل نبود، خودش وصل شود
}
```

### ۳. رول بات

بات با پرمیشن‌های **همان کاربری** که کلاینت با آن وصل شده کار می‌کند. به این identity یک سرور گروپ
بدهید که این‌ها را داشته باشد:

| پرمیشن | برای چه |
|---|---|
| `i_group_member_add_power` | دادن رول — باید از `i_group_needed_member_add_power` رول CMT بیشتر باشد |
| `i_group_member_remove_power` | گرفتن رول |
| `b_virtualserver_servergroup_client_list` | `!cmts` و اسم چنل‌ها |
| `b_virtualserver_client_dblist` | پیدا کردن کاربر آفلاین |
| `b_channel_modify_name` + `i_channel_modify_power` | تغییر اسم چنل‌ها |
| `b_client_server_textmessage_send` / `b_client_channel_textmessage_send` | جواب دادن در چت |

اگر بات وصل شد ولی رول نداد، معمولاً مشکل **`i_group_member_add_power`** است.

### ۴. تگ `[CMT Server]` کنار اسم و بالا بودن در لیست

همان چیزی که در سرورها به شکل `[VIP]` کنار اسم می‌بینید. تیم‌اسپیک خودش آن را رندر می‌کند،
پس با گرفتن رول خودکار می‌آید و با پس گرفتنش خودکار می‌رود.

```
node set-group-display.js --show           وضعیت فعلی همه گروه‌ها
node set-group-display.js                  تگ قبل از اسم
node set-group-display.js --sort 1         تگ + بردن اعضا به بالای لیست
node set-group-display.js --mode 2         تگ بعد از اسم
node set-group-display.js --mode 0 --sort 0    برگرداندن همه‌چیز
```

هر دو مورد در واقع **پرمیشن روی خود گروه** هستند، نه پراپرتی گروه — دستور `servergroupedit`
اصلاً در تیم‌اسپیک ۳ وجود ندارد:

| پرمیشن | مقدار |
|---|---|
| `i_group_show_name_in_tree` | `0` مخفی · `1` قبل از اسم · `2` بعد از اسم |
| `i_group_sort_id` | عدد کمتر = بالاتر. `0` یعنی بدون ترتیب (ته لیست) |

`--show` همه گروه‌ها را به ترتیبی که در تری مرتب می‌شوند چاپ می‌کند تا عدد مناسب را انتخاب کنید.
اگر دو گروه عدد یکسان بگیرند، ترتیبشان نسبت به هم تعریف‌شده نیست و اسکریپت هشدار می‌دهد.

> اسکریپت از همان اتصال ClientQuery بات استفاده می‌کند، پس **هیچ یوزر و پسورد ServerQuery
> لازم ندارد**. فقط کافی است کلاینت تیم‌اسپیک باز باشد.
>
> در تیم‌اسپیک هیچ کلاینتی نمی‌تواند نیک‌نیم کلاینت دیگری را عوض کند (`clientupdate` فقط روی
> کلاینت خودتان کار می‌کند)، برای همین تگ باید از سمت خود رول بیاید.

### ۵. اجرا

`start.bat` را اجرا کنید (خودش ری‌استارت می‌کند). موقع بالا آمدن، لیست کامل سرور گروپ‌ها با
آی‌دی‌شان در کنسول چاپ می‌شود تا `groups` را درست پر کنید.

## بقیه تنظیمات `config.json`

### `commands`

هر دستور می‌تواند چند اسم داشته باشد:

```jsonc
"commands": {
  "caseSensitive": false,
  "cmtserver": ["!cmtserver", "!cmtsrv"],
  "cmtticket": ["!cmtticket", "!tk"],
  "list": ["!cmts", "!cmtlist"],
  "help": ["!cmthelp"]
}
```

### `groups` و `channels`

```jsonc
"groups":   { "cmtserver": 91, "cmtticket": 92 },
"channels": {
  "enabled": true,
  "cmtserver": 86,
  "cmtticket": 87,
  "nameTemplate": {
    "cmtserver": "CMT Server : {users}",
    "cmtticket": "CMT Ticket : {users}"
  },
  "separator": ", ",
  "emptyText": "-",
  "maxNameLength": 40,
  "updateOnStart": true,
  "refreshIntervalSeconds": 0    // مثلاً 300 = هر ۵ دقیقه هم آپدیت کن
}
```

آی‌دی چنل: راست‌کلیک روی چنل → Edit Channel → Channel ID.

### `permissions`

```jsonc
"permissions": {
  "adminGroups": [],       // فقط این گروه‌ها به «دیگران» رول بدهند. خالی = همه
  "allowedGroups": [],     // فقط این گروه‌ها از بات استفاده کنند. خالی = همه
  "allowSelfAssign": true  // false: کسی به خودش رول ندهد
}
```

### `clientquery`

```jsonc
"clientquery": {
  "host": "127.0.0.1",
  "port": 25639,
  "apiKey": "",        // خالی = خودکار از clientquery.ini
  "apiKeyFile": "",    // خالی = %APPDATA%\TS3Client\clientquery.ini
  "maxDbSearch": 500   // چند آیدنتیتی برای پیدا کردن کاربر آفلاین گشته شود
}
```

### `messages`

همه متن‌ها فارسی و قابل تغییرند. BB-code تیم‌اسپیک (`[b]...[/b]`) کار می‌کند.
جایگزین‌ها: `{user}`، `{group}`، `{count}`، `{error}`.

## نکته: زیرنویس چنل‌ها

`clientlist` فقط کاربرانِ چنل‌هایی را می‌بیند که کلاینت **subscribe** کرده است. برای اینکه بات
همه کاربران آنلاین را با اسم پیدا کند، در کلاینت روی سرور راست‌کلیک کنید →
**Subscribe to all channels**.

بدون آن هم کار می‌کند (بات سراغ دیتابیس سرور می‌رود) ولی کندتر است.

## مشکلات رایج

| پیام | راه‌حل |
|---|---|
| `could not reach the ClientQuery plugin` | کلاینت TS3 باز نیست، یا پلاگین ClientQuery فعال نیست. |
| `could not read the ClientQuery api key` | مسیر `clientquery.ini` را در `clientquery.apiKeyFile` بدهید. |
| `the client did not finish connecting` | آی‌پی/پورت غلط، یا سرور بن/بلک‌لیستتان کرده. لاگ کلاینت را در `%APPDATA%\TS3Client\logs` ببینید. |
| `could not rename channel X` | آی‌دی چنل غلط، اسم تکراری با چنل دیگر، یا نداشتن `b_channel_modify_name`. |
| `no server group with sgid X exists` | آی‌دی رول در `groups` غلط است — لاگ لیست گروه‌ها را ببینید. |
| رول داده نمی‌شود | `i_group_member_add_power` بات کمتر از `i_group_needed_member_add_power` رول CMT است. |
